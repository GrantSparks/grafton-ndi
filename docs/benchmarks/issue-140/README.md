# Issue #140 implementation and evidence

This series implements runtime JPEG SIMD, direct packed-RGB JPEG input,
notification-aware capture retries, continued File event draining, shorter
owned-source cache critical sections, and reusable image conversion scratch.
Existing borrowed/scoped captures, reusable owned copies and sender staging
remain the preferred application paths.

## Scope and remaining gates

| Area | Implemented behavior | Qualification boundary |
| --- | --- | --- |
| JPEG SIMD | `jpeg-encoder` runtime AVX2 dispatch with portable fallback | Independent decoder, x86 AVX2 and emulated scalar tests; ARM64 compile |
| JPEG input | Borrow full-size contiguous RGBA/RGBX/BGRA/BGRX; retain rows for padding, YUV and reductions | No full-image conversion buffer added; metadata/HDR validated first |
| Capture | Retry eight notifications immediately, back off on the ninth or on an idle early return | Fake-clock storm/deadline tests and native notification/reconnect regressions; no native notification-to-frame latency claim |
| File | Check commands without waiting after 16 events; wait after empty/error | Deterministic fairness/shutdown/error/drop tests and native File regressions; fake-owner burst throughput only |
| Cache | Clone immutable snapshot handles while locked, copy descriptors after unlocking; prepare publications outside the mutex | Invalidation during copying/discovery, generation exhaustion and public input validation covered |
| Workspace | Retain PNG row, WebP conversion image and 8/16-bit reduction sums; explicit capacity release | Warm conversion allocation tests, output/error recovery tests and public encode measurements |
| Continuous async | Keep one-shot APIs; add dispatch and public audio baseline harnesses | No streaming API ships: representative loaded-pool, slow-consumer, memory/backpressure and worker-prototype comparison remains a gate |

Miss coalescing is deliberately separate from the cache critical-section change.
Two calls with different start times require different complete observation
windows, even with equal timeout durations. This series does not elect leaders
or change those windows. A shared-window API or a demonstrably compatible
request identity needs its own design and validation. Existing independent
misses retain their failure, panic and cancellation behavior.

These changes do not close the issue's platform/native/performance qualification
checklist. In particular, synthetic fixtures and one host do not establish
release speedups, native File backlog rates, production discovery throughput,
or streaming-worker benefits. No codec defaults other than enabling runtime
JPEG SIMD changed; WebP effort and SharpYUV defaults remain unchanged.

  `0144e8d` (raw samples, one warmup, input SHA-256 identities and optional dumps).
- Linux x86-64, Intel Xeon w7-2475X, AVX2; shared host, default Rust CPU target.
- Stable Rust 1.100.0 (`0ef1bc386`, LLVM 23.1.5); minimum-version checks use 1.88.0.
- Locked dependencies, including `jpeg-encoder 0.7.1`, `jpeg-decoder 0.3.2`,
  `png 0.18.1`, `image-webp 0.2.4`, `libwebpop 0.1.0`.
- Independent comparison: Pillow 13.0.0, NumPy 2.4.6. Synthetic photographic and
  graphics inputs from `content_rgba`; hashes are retained in every image log.
- Raw logs normalize trailing whitespace and final newlines only. Inputs/encoded dumps are optional
  scratch artifacts, regenerated by the retained harness. No vendor files are
  included.

Run the JPEG harness at the scalar, SIMD-only and direct-input commits in this
series, using a different dump directory for each:

```sh
GRAFTON_NDI_SIZES=640x360,1920x1080,3840x2160 \
GRAFTON_NDI_OUTPUTS=jpeg85,jpeg85-quarter \
GRAFTON_NDI_IMAGE_DUMP=/tmp/issue-140-scalar \
  cargo test --release --locked --lib --features image-encoding \
  image_encoding_resources -- --ignored --nocapture

python scripts/compare-jpeg.py /tmp/issue-140-scalar \
  /tmp/issue-140-simd /tmp/issue-140-direct
```

Each format/content/size/output has one unmeasured warmup and five raw samples.
Timing includes public frame option/layout/color handling, conversion, output
allocation and encoding. It excludes source construction, capture/transport,
decode, base64 and thread startup. Peak heap tracks live allocations on the
encoding thread, excluding preexisting source storage. Raw samples, medians,
input identities and output sizes appear in `jpeg-{scalar,simd,direct}.txt`.
Second rounds use separate test-process invocations and are retained separately.
Harnesses use no global `target-cpu=native`.

## JPEG observations

Scalar/SIMD-only/direct revisions are `0144e8d`, `d338090` and `c8ef104`.
`jpeg-build-cost.txt` retains the exact standalone dependency/harness compiler
commands, elapsed compile time and object/executable sizes; these isolate the
backend and do not measure the complete library build. The tiny direct-encode
executable gained approximately 240 KB of text with SIMD; dependency compile
time was under one second for each configuration on this host. This is a real
code-size tradeoff, not a claim of zero-cost acceleration.

First-round public `encode_image` wall-clock medians, synthetic photographic
RGBA, quality 85, milliseconds:

| Size | Scalar rows | SIMD rows | SIMD direct |
| --- | ---: | ---: | ---: |
| 640 × 360 | 2.6 | 2.4 | 2.2 |
| 1920 × 1080 | 23.2 | 21.2 | 19.7 |
| 3840 × 2160 | 92.0 | 84.0 | 77.5 |

The full logs also include UYVY, NV12, P216, NA4G, graphics and quarter-size
output. YUV conversion and reduction can dominate; the table is not a network
or all-format speedup. No full-image intermediate was added for PNG/JPEG.

`jpeg-decoded.csv` retains independent decoding of 180 images (three variants,
five source formats, two contents, three sizes, full/quarter output). Relative
to decoded scalar output, the largest observed mean absolute channel difference
was 0.062969 and the largest individual difference was 15 codes. The comparison
script enforces mean <= 1 and max <= 32; these bounds are test tolerances for
this corpus, not universal codec equivalence. PSNR uses the original synthetic
RGB before YUV quantization; quarter-size references average blocks.

Rust regressions independently decode RGBA/RGBX/BGRA/BGRX at qualities 50, 85,
89, 90, 91 and 100, with even widths around eight/sixteen-pixel boundaries and
odd heights. They check channel order/alpha discard and compare direct input
to component rows (mean <= 1, max <= 16). Existing tests cover all YUV formats,
padding, reduction, invalid options/HDR before output and writer errors. PNG
legacy hashes remain enforced. Scalar JPEG legacy hashes also remain enforced
when AVX2 is unavailable; accelerated bytes intentionally have no legacy hash.

`jpeg-fallback.txt` was produced with QEMU user 7.2.22, `-cpu Nehalem`, running
the release JPEG decoder tests and legacy hash test. The test reports
`JPEG AVX2=false`. This exercises the dependency's runtime fallback without
removing the SIMD Cargo feature. It is emulation, not non-x86 runtime testing.

## Cache, File and async scheduling

```sh
cargo test --release --locked --all-features --lib resources -- \
  --ignored --nocapture --skip image_encoding_resources --skip workspace_resources

GRAFTON_NDI_REQUIRE_RUNTIME=1 cargo test --release --locked --all-features \
  --config ci/offline.toml --test async_capture_performance -- --ignored --nocapture
```

`scheduling-cache.txt` retains three SDK-free harnesses, run with libtest's
default parallelism. The cache harness
compares the old locked deep copy with the public cache kernel, using 1/128/4096
owned sources and 1/8 concurrent callers, 100 hits per lane, three rounds. At
4096 sources and eight callers, median lane time per lookup was approximately
2.63 ms with locked copying versus 0.39 ms with snapshots. One-source cases
were slightly slower with snapshots. The benchmark does not model native
discovery, misses or process RSS. Cache storage adds one Arc allocation per
entry; a caller in flight can retain an old immutable snapshot through
invalidation until its copy finishes. Source-count/string-copy budgets remain
unchanged; the native snapshot lock still protects SDK-owned descriptors.

The fake File owner delivers 1600 events, checking commands every 16, over five
samples. It compares old timed command waits with the new nonblocking checks.
Median last-burst latency was approximately 996 ms versus 0.124 ms; timed waits
after full bursts fell from 100 to zero. Both paths drop 1584 notifications in
the intentionally tiny 16-entry consumer queue. This measures the artificial
wait alone, with cheap fake events. Deterministic tests verify that idle/error
paths request a timed wait, commands run between bursts, and shutdown is
serviced after at most one burst. Native event rates and idle CPU need separate
qualification.

The dispatch harness measures the existing cancellation gate and blocking-pool
round trip (no SDK), 10 warmups then 100 samples per lane, with 1/8 callers,
Tokio and Smol separately. Median latency was approximately 9–11 microseconds;
this excludes realistic blocking-pool load and does not count worker allocations.

`async-audio.txt` uses the public scoped audio capture APIs over native loopback
with Standard 6.3.2, 48 kHz stereo, 48/480-sample blocks, 1/8 simultaneous
streams, and 0/50-microsecond callback work. Each lane warms up for 20 delivered
items, then retains 100 submission-to-callback-completion samples. The sender
sets a monotonic timestamp in timecode immediately before submission, paces
independently and does not catch up after scheduler delay. Initial discovery,
connection and teardown are excluded. Pooled p50 was approximately 56–89 us
without callback work; p99 was 79–150 us. With callback work, p50 was 100–140 us
and p99 123–190 us. No hard latency assertion or continuous-worker benefit is
inferred. This is a small loopback baseline, not a loaded-pool, retention,
shutdown or overload qualification; it does not count dropped audio or RSS.

## Workspace memory

```sh
cargo test --release --locked --lib --features image-encoding \
  workspace_resources -- --ignored --nocapture
```

`workspace.txt` compares cold versus warm conversion storage through public
`ImageWorkspace::encode`, three samples after warmup, padded BGRA at 1080p/4K,
PNG fast, lossless WebP, reduced WebP and lossy WebP effort 0 without SharpYUV.
Columns are width, height, output, warm, sample, elapsed ms, allocation count,
peak newly-live thread heap bytes, scratch retained before/after, source storage
bytes, output length, and process VmRSS KiB before/after (Linux; zero elsewhere).
The source bytes are interpreted as BGRA; the deterministic photographic RGBA
generator supplies their byte values without a red/blue swap.

For 4K lossless WebP, cold/warm allocation counts were 78/77. Warm storage
retained 33,177,600 conversion bytes. Newly-live encode heap dropped from
83,132,416 to 49,954,816 bytes because the scratch existed before tracking;
adding retained scratch gives the same working set. Process RSS snapshots were
148,492 KiB in this run. This demonstrates allocation reuse, not reduced peak
memory or RSS. Codec and encoded output still allocate. Lossy `encode` retains
the backend's original output vector, with no second wrapper output copy.

Warm-stage tests separately exclude codecs/output and prove zero wrapper
conversion allocations across all input formats, padding, smaller sizes,
alpha modes, reductions and both PNG depths. Borrowed eligible RGBA retains
zero conversion capacity. Public output/error tests check format/size changes,
different images, writer failure, invalid options and release/reuse.

## Validation

- `cargo test --locked --all-features --config ci/offline.toml`: complete suite,
  Standard 6.3.2 selected from the installed SDK; compile contracts, fake libraries,
  native tests and rustdoc tests passed. Runtime/capability skips retain their
  existing prerequisite policy.
- Targeted `--lib`, notification, async events, mixed capture, File loading,
  File source selection and File race regressions passed with Advanced 6.4.0.2
  headers/runtime and `GRAFTON_NDI_REQUIRE_RUNTIME=advanced,file`, isolated to
  loopback. Native runtime identity was printed by the tests. These establish
  correctness behavior, not comparative performance.
- Clippy with warnings denied: all features/all targets under Standard and
  Advanced headers; independent default, Advanced, image, Tokio and Smol
  combinations also run by the repository's commit hooks.
- Rust 1.88: all-feature library checks on x86-64 and ARM64. Its preexisting
  `RuntimeFeature::is_ungated` dead-code warning remains; stable Clippy is clean.
- ARM64 was compiled only. Windows/Apple and oldest Advanced headers were not
  exercised in this implementation session. Runtime SIMD fallback was emulated.
- New public workspace API is covered by a compile-pass trait-object fixture,
  runnable rustdoc and image tests. Existing ownership/cancellation gates remain.
