# Migrate from 2.x to 3.0

Set `grafton-ndi = "3.0"` and use Rust 1.88 or later. This guide compares the
released 2.0 API with the final 3.0 API; [older upgrades](README.md) are archived.
The [setup guide](../setup.md) owns current platform and runtime requirements.

Check these changes even after the compiler accepts your application:

- FrameSync's short capture names now copy; use `_ref` to keep borrowing.
- Capture waits through transient SDK results for the full timeout; `None`
  means the deadline expired, not merely that one native call returned early.
- `ReceiverOptions::new` allows video fields; the old `Default` did not.
- New video builders request square pixels and default to 60 fps.
- Borrowed frame `data()` excludes storage after the validated frame.
- Runtime selection and borrowed-video send staging can change deployment and
  copying behavior. Review [runtime](#runtime-and-deployment) and
  [sending](#sending).

## Dependency and names

No Cargo features are enabled by default. Explicitly enable `image-encoding`
for image methods and `ImageFormat`. Remove the ineffective `advanced_sdk`
feature. The new `advanced` feature is a separate API, not its replacement.
If using `#[tokio::main]` or Tokio's multithreaded runtime, enable Tokio's
`macros` and `rt-multi-thread` yourself; this crate enables only `rt`.

| 2.0 | 3.0 |
| --- | --- |
| `NDI` | `Ndi` |
| `PixelFormat::BGRA`, `UYVY`, `NV12`, … | `Bgra`, `Uyvy`, `Nv12`, … |
| `ReceiverColorFormat::RGBX_RGBA`, `UYVY_BGRA`, … | `RgbxRgba`, `UyvyBgra`, … |
| `AudioFormat::FLTP` | `AudioFormat::Fltp` |
| `grafton_ndi::tokio::AsyncReceiver` | `grafton_ndi::asynchronous::tokio::AsyncReceiver` |
| `grafton_ndi::smol::AsyncReceiver` | `grafton_ndi::asynchronous::smol::AsyncReceiver` |

The crate root no longer shadows the `tokio` or `smol` dependency names.

## Runtime and deployment

Desktop and Android builds load NDI at runtime instead of linking it at build
time. They need no build-time SDK for the default features. Advanced native
operations still need Advanced headers and `libclang`; Apple mobile targets
still link a static SDK archive. See [build requirements](../setup.md#build-requirements).

- Handle `Error::RuntimeLoadFailed` from initialization when the library is
  missing. A missing dynamic library no longer prevents the process starting.
- Package the runtime explicitly: executable dependency scanners cannot find a
  dynamically selected library.
- Check the [search order](../setup.md#finding-the-runtime). Executable-local
  libraries and `NDI_RUNTIME_DIR_V6` precede the system loader. Request
  `SdkEdition::Advanced` when needed; an SDK installed on the build machine no
  longer chooses the runtime edition.
- Select once with the intended options. Successful selection lasts for the
  process; selecting another library later returns `Error::RuntimeConflict`.
- Code declaring its own NDI `extern "C"` functions must link its own library;
  this crate no longer supplies that link or exposes its loaded symbols.
- Keep a runtime in test jobs that exercise NDI. Ordinary compile-only jobs
  need none; remove stale SDK environment variables where they are unnecessary.

| Removed API | Replacement |
| --- | --- |
| `NDI::is_supported_cpu()` | `Runtime::select(&options)?.is_supported_cpu()`, or `ndi.runtime().is_supported_cpu()` |
| `NDI::version()?` | `ndi.info().raw_version()`, or `Runtime::select(&options)?.info().raw_version()` before initialization |

The replacement version expression borrows runtime information rather than
returning a `String`; call `.to_owned()` where ownership is required.

## Options

Options have private fields and chainable setters. Remove the options builders
and their final `.build()`:

```diff
-let finder_options = FinderOptions::builder().show_local_sources(false).build();
+let finder_options = FinderOptions::new().show_local_sources(false);
-let options = ReceiverOptions::builder(source).color(ReceiverColorFormat::RGBX_RGBA).build();
+let options = ReceiverOptions::new(source).color_format(ReceiverColorFormat::RgbxRgba);
-let options = SenderOptions::builder("Camera 1").clock_audio(false).build();
+let options = SenderOptions::new("Camera 1").clock_audio(false);
```

`FinderOptionsBuilder`, `ReceiverOptionsBuilder` and `SenderOptionsBuilder` are
removed. Receiver presets move to `ReceiverOptions` itself. Replace the public
`ndi_recv_name` field with `.name(...)`, and inspect settings with
`configured_*()` getters. These report requested configuration, not runtime
acceptance. Struct literals and direct field reads must change.

`ReceiverOptions` has no `Default`: construct it with a source.
`ReceiverOptions::new(source)` allows video fields, matching the old builder;
add `.allow_video_fields(false)` to preserve the old `Default` behavior.
Finder local-source visibility, sender clocks and receiver color/bandwidth
keep their old defaults.

## Sources

Construct sources with `Source::new(name).with_address(address)` and read them
with `name()` and `address()`. `address()` returns `Option<&SourceAddress>`;
`SourceAddress::None`, and `Default` for both types, are removed.
`Source::host()` replaces `ip_address()` and may return a URL hostname.

Choose an exact feed with `finder.find_source_by_name(name, timeout)`, or
`find_source(timeout, predicate)` to disambiguate descriptors. The first
matching descriptor wins; duplicate names need an application predicate.

```diff
-let cache = SourceCache::new();
-let source = cache.find_by_host("192.168.1.100", timeout)?;
+let cache = SourceCache::new(finder);
+let feeds = cache.sources_by_host("192.168.1.100", timeout)?;
```

The cache **owns the configured Finder**, including its runtime lifetime and
discovery scope. It has no lifetime parameter or `Default`; move the finder
into it and use `cache.finder()` for later uncached lookups. `sources_by_host`
returns all distinct matching feeds observed over the complete window; select
the desired feed yourself. Entries remain stale until invalidated. See the
[server-state recipe](../usage.md#keep-discovery-in-server-state).

Finder results and discovery windows now enforce count and byte limits and
return `Error::ResourceLimit` rather than a partial result. A lookup's timeout
also covers snapshot-lock waits. Zero makes one non-waiting attempt, but native
copying and application predicates are not interrupted. Oversized timeouts are
rejected even on cache hits.

## Frames

Widths, heights, rates and counts move from `i32` to `u32`; strides move to
`usize`. Buffer-length results were already `usize` in 2.0. Values outside the
signed native ABI range are rejected before submission.

| 2.0 | 3.0 |
| --- | --- |
| `VideoFrameBuilder::new()` | `VideoFrame::builder()` |
| `AudioFrameBuilder::new()` | `AudioFrame::builder()` |
| `.frame_rate(n, d)` | `.frame_rate(FrameRate::new(n, d)?)` |
| `.aspect_ratio(ratio)` | `.picture_aspect_ratio(ratio)` |
| `.channels(n)`, `.samples(n)` | `.num_channels(n)`, `.num_samples(n)` |
| `.channel_stride_in_bytes()` | `.channel_stride_bytes()` |
| `.frame_rate_n()`, `.frame_rate_d()` | `.frame_rate().numerator()`, `.frame_rate().denominator()` |
| `.line_stride_or_size()` and `LineStrideOrSize` | `.line_stride_bytes()` |
| `PixelFormat::try_line_stride(width)` | `PixelFormat::line_stride_bytes(width)` |
| `PixelFormat::try_buffer_size(width, height)` | `PixelFormat::buffer_len(width, height)` |
| `PixelFormatInfo::try_buffer_len(stride, height)` | `PixelFormatInfo::buffer_len(stride, height)` |

`VideoFrame`, `AudioFrame`, `MetadataFrame`, `VideoFrameBuilder` and
`AudioFrameBuilder` lose `Default`. `AudioFrameBuilder::format` is removed because audio uses
`AudioFormat::Fltp`. Frame-rate setters take an
already validated `FrameRate` and no longer return `Result`. Rates compare and
hash by value (`30/1 == 60/2`), while retaining their supplied numerator and
denominator for accessors and submission.

**Review defaults.** Owned and borrowed video builders store the SDK square-pixel
aspect request, `0.0`, instead of a fixed display ratio. Set a positive
`picture_aspect_ratio` for anamorphic output. Owned and borrowed video builders
and `VideoPacketFormat::new` default to 60 fps; explicitly choose another rate
when required. Copies preserve supplied timing and aspect.

Use `Timecode::from_ticks(value)` instead of raw `i64`; `.ticks()` extracts it.
The default remains `Timecode::SYNTHESIZE`. Create metadata with
`MetadataFrame::new(text)?.with_timecode(timecode)`, replacing
`MetadataFrame::with_data(text, ticks)` and empty `new()`.
Received timestamps are `Option<SdkTimestamp>` instead of raw `i64`.
Delete send-frame timestamp setters and `BorrowedVideoFrame::timestamp`.

Use `FourCc::from(pixel_format)`, `fourcc.raw()` and
`PixelFormat::try_from(fourcc)` instead of raw integer conversions for pixel
formats. `ScanType` and `AudioFormat` also lose their raw integer conversions.

Borrowed media `to_owned()` is infallible, including FrameSync references;
remove `?`. `BorrowedVideoFrame::try_to_owned` becomes `to_owned`. Reuse existing
storage with `copy_into`. `VideoFrame::from_raw` is removed.

Owned video/audio `set_metadata(Some(text))` becomes `set_metadata(text)`;
`set_metadata(None)` becomes `clear_metadata()`. Invalid replacement metadata
leaves the old value intact.

`VideoFrameBuilder::build`, `AudioFrameBuilder::build` and owned-frame
`replace_data` return refused input in `Rejected<T>`. `?` still converts it to
`Error`. When returning the result directly, use
`Ok(builder.build()?)` or `.map_err(Error::from)`. Inspect `rejected.error()`
and recover input with `into_inner()` instead of discarding reusable storage.

## Receiving

Capture returns `Result<Option<Frame>>`: handle timeout as `None` instead of
`Error::FrameTimeout`. Remove `try_capture`; rename `try_capture_ref` to
`capture_ref`. Async capture follows the same rule.

```diff
-if let Some(frame) = receiver.video().try_capture(timeout)? {
+if let Some(frame) = receiver.video().capture(timeout)? {
     println!("{}x{}", frame.width(), frame.height());
 }
```

Unlike the old `try_*` methods, capture retries transient SDK results until a
frame arrives or the full deadline is spent. Use `Duration::ZERO` for one
non-waiting attempt. `CaptureKind::ref_to_owned` is private; call the frame's
`to_owned()`.

`Receiver::source()` becomes `connection_target()`, an owned snapshot of the
last requested target. `connect_to(B)` changes it to B, `disconnect()` retains
B and `reconnect()` retries B. Retain the original source yourself to return
to it. Observe actual source changes with `poll_source_name_change`.

`Receiver::poll_status_change(timeout)` becomes `poll_event(timeout)`:

```diff
-if let Some(status) = receiver.poll_status_change(timeout)? {
-    println!("connections: {}", status.connections);
+if let Some(ReceiverEvent::StatusChanged(status)) = receiver.poll_event(timeout)? {
+    println!("connections: {}", status.connections());
 }
```

It can also return source-change and unknown events, and waits through
transient results for the full timeout. Combined capture and `poll_event`
consume pending events once; typed capture retains them for either consumer.
Notifications coalesce and are not a broadcast or ordered history.

| Receiver API | Required generic mode bound |
| --- | --- |
| Common controls | `ReceiverMode` |
| Metadata capture and event polling | `MetadataMode` |
| Audio capture | `CaptureMode` |
| Video capture | `VideoMode` |

Update generic functions previously bounded only by `ReceiverMode`.
FrameSync's attached receiver exposes metadata and controls, not raw audio or
video. Capture through FrameSync, or call `into_receiver()` first.

PTZ moves to `receiver.ptz()`: remove the `ptz_` method prefix, rename
`ptz_exposure_manual_v2` to `exposure_manual_detailed`, and pass preset indices
as `u8` in `0..=99`. Rejected commands return `NativeOperationFailed`.
`set_tally` takes `Tally` by value and returns `()`; `send_metadata` returns
`Result<()>`, with `Error::NotConnected` where it previously returned `false`.
`Tally`, `ReceiverStatus` and `ConnectionStats` expose getters instead of
public fields, for example `tally.on_program()` and `stats.connections()`.

## FrameSync

**The short capture names now return owned copies.** Calls using only common
frame methods may still compile while introducing a copy:

```diff
-let video = framesync.capture_video(ScanType::Progressive)?;
+let video = framesync.capture_video_ref(ScanType::Progressive)?;
-let audio = framesync.capture_audio(request)?;
+let audio = framesync.capture_audio_ref(request)?;
```

Rename `capture_video_owned` to `capture_video`, and `capture_audio_owned` to
`capture_audio`, when you want owned output. `FrameSync::new` returns a
rejected receiver in `Rejected<Receiver>` on failure; `?` still converts it.

`FrameSyncAudioRequest::capture_with(Some(rate), channels, samples)` becomes
`capture_at(rate, channels, samples)`, with unsigned dimensions. Requests must
specify a positive sample rate. Replace `capture_with(None, ...)` and the
input-format query with:

```diff
-let input = framesync.capture_audio(FrameSyncAudioRequest::query_input())?;
-if input.num_channels() > 0 {
-    let request = FrameSyncAudioRequest::capture_with(None, input.num_channels(), 1_024)?;
+if let Some(input) = framesync.audio_input_format()? {
+    let request = FrameSyncAudioRequest::for_input(input, 1_024)?;
```

`capture_audio` returns `AudioFrame`, not `Option<AudioFrame>`; the borrowed
version returns `FrameSyncAudioRef`. Remove `is_empty` checks; `format()` and
`to_owned()` return their values directly. `audio_queue_depth()` is `u32`.
Do not use clocked output or a known format as proof of recent input; use the
[reception-monitor recipe](../usage.md#monitor-reception-of-the-expected-media).

## Sending

`send_video(&frame)` now returns `Result<()>`; `send_video_async(frame)` can
return `Rejected<VideoFrame>`. Use `?`, or recover an unsent frame with
`into_inner()`. Sends check the runtime's format capabilities before submission.

`sender.tally()` returns the current tally. Replace the old
`tally(timeout)` with `wait_for_tally_change(timeout)` when waiting for a
change; polling no longer loses the current state after the first read.

Synchronous video/audio operations borrow a shared reference to a validated
source, including captured frames. Remove `BorrowedVideoFrame::from(&owned)`
and old `Into<BorrowedVideoFrame>` adapters. Use `send_video_async_copy(&frame)`
to copy a captured or borrowed frame into owned storage before submission.
`Sender` still means `Sender<RawSend>`; generic senders use `SenderMode`, with
`AudioSendMode` required for audio sends.

Construct borrowed video with the builder:

```diff
-let frame = BorrowedVideoFrame::try_from_uncompressed(&pixels, 1920, 1080, PixelFormat::BGRA, 30, 1)?;
+let frame = BorrowedVideoFrame::builder(&pixels, 1920, 1080, PixelFormat::Bgra)
+    .frame_rate(FrameRate::new(30, 1)?)
+    .build()?;
```

Use `line_stride_bytes(usize)`, `frame_rate(FrameRate)` and
`timecode(Timecode)`. Replace `fourcc()` with `FourCc::from(frame.pixel_format())`,
and `validated_data_len()` with `data().len()`. `data()` now covers validated
frame storage, including row padding, **not the whole original input slice**.

On targets needing SDK tail room, borrowed UYVY/UYVA sends stage active rows
with a zeroed tail by default; padded captures also stage active rows. The
sender reuses staging storage.
Inspect `VideoSource::sends_in_place(&frame)` when this matters to your pipeline.
For direct borrowed sending, explicitly opt into
`allow_send_from_padding_and_tail(true)` and provide the length computed by
`PixelFormat::send_buffer_len`. This permits encoding initialized padding and
tail bytes into the picture. `unsafe readable_after` alone does not opt in;
its bytes must be initialized, stable and in the same live allocation. Keep
this choice explicit rather than removing the default sanitization.

## Image encoding

Enable `image-encoding` and import `ImageFormat` from the crate root. Existing
`encode_png`, `encode_jpeg` and `encode_data_url` signatures remain, with these
behavior changes:

- JPEG quality outside `1..=100` is `InvalidInput`, previously `InvalidFrame`.
- PQ/HLG frames are refused by default, including RGB. To retain their code
  values, request PNG with `HdrPolicy::CodeValues`.
- Unreadable `ndi_color_info` is refused under the default color policy. Use
  `ColorPolicy::Override { matrix, range }` only when the application can
  supply that information.
- PNG carries BT.2020 color metadata where applicable, changing encoded bytes.
- YUV formats can encode; do not use an `InvalidFrame` result to identify them.
- `ImageFormat` gains `WebpLossless` and `WebpLossy(quality)`.

See [image encoding](../image-encoding.md) for current format and color choices.

## Errors and timeouts

| 2.0 variant | 3.0 handling |
| --- | --- |
| `InvalidConfiguration` | `InvalidInput` |
| `FrameTimeout` | Capture returns `Ok(None)` |
| `NullPointer`, `PtzCommandFailed` | `NativeOperationFailed`, naming the native operation |
| `Timeout` from a negative connection count | `UnexpectedSdkResult` |
| `SourceUnavailable`, `Disconnected` | Delete unused match arms; 2.0 never returned these |

A CPU missing required instructions yields `UnsupportedCpu`; SDK object creation
failure yields `NativeOperationFailed`. `InitializationFailed` now means runtime
initialization failed. `Error::Io` is available only with `file-io` or
`image-encoding`. Keep a wildcard arm for the non-exhaustive error enum.
`ResourceLimit` uses typed `ResourceKind` values rather than string matching.

`MAX_TIMEOUT` is `u32::MAX - 1` milliseconds. The old hard-coded maximum is
rejected because the SDK interprets it as infinite. Nonzero fractional
milliseconds round up, so sub-millisecond calls can now wait one millisecond;
use `Duration::ZERO` to poll.

## Adapting pre-release 3.0 applications

Applications tracking 3.0 development snapshots should also check these final
names and contracts:

- `SourceCache::new(finder)` takes ownership; remove any `SourceCache<'a>` type
  arguments and use `cache.finder()` for uncached lookups.
- `PacketItem` replaces `PacketEvent`, with notifications under
  `PacketItem::Event(ReceiverEvent)`. Status events carry the current connection
  snapshot and share the coalesced event-consumption rules above.
- `CompressedSender::close()` returns `ReclaimedVideo`, not `UnsentVideo`;
  reclaimed program/preview frames carry no delivery verdict.
- `AvSyncOutcome` no longer has `InternalError` or `Unknown` outcomes.
  `synchronize(...)?` reports `NativeOperationFailed` or `UnexpectedSdkResult`;
  lack of matching audio and format changes remain ordinary outcomes.
- Compressed/scatter frames use mutable `set_metadata`, `clear_metadata`,
  `set_timecode` and audio `set_protected`, rather than consuming `with_*`
  methods. Empty metadata and absent metadata remain distinct. Reusable
  `VideoPacketFormat` keeps its fluent setters.
- `PlayerStats::video_frames` takes `StreamTier::Program` or `Preview` instead
  of returning an array. Recorder dropped-frame and last-PTS getters name the
  media, such as `video_frames_dropped_by_receiver()` and `last_audio_pts()`.
- Async recorder `inject_metadata` accepts `MetadataSource`, copying text and
  timecode when called; captured metadata needs no preliminary owned copy.
- Attached Advanced stream controls use `controls()`. Use `split()` to borrow
  capture and KVM controls together; drop borrowed views before recovering the
  receiver.
- Async File operations submit on first poll, or explicitly with `.submit()`.
  Dropping an unsubmitted future starts no work. Submitted stop/finish/close
  operations run even if their futures are dropped. Deadlines start at
  submission. See [File API](../file-io.md) for cancellation and finalization.
