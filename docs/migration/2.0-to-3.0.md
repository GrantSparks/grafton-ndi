# Migrate from 2.x to 3.0

Set `grafton-ndi = "3.0"` and use Rust 1.88 or later. This guide compares the
released 2.x APIs with 3.0; [older upgrades](README.md) are archived.
The [setup guide](../setup.md) owns current platform and runtime requirements.

Check these changes even after the compiler accepts your application:

- FrameSync's short capture names now copy; use `_ref` to keep borrowing.
- Capture waits through transient SDK results for the full timeout; `None`
  means the deadline expired, not merely that one native call returned early.
- `ReceiverOptions::new` allows video fields; the old `Default` did not.
- New video builders request square pixels and default to 60 fps.
- Borrowed frame `data()` excludes storage after the validated frame.
- Runtime selection and borrowed-video send staging can change deployment and
  copying behavior. Review [runtime](#runtime-and-deployment) and
  [sending](#sending).

Captured video and audio no longer fail solely because optional per-frame
metadata is not UTF-8 or lacks a terminator within the metadata cap. Code that
matched `InvalidUtf8` or `InvalidFrame` for that side text should inspect
`frame.metadata_status()` instead. `metadata()` returns `None` for unreadable
text, which forwarding and owned copies omit. Owned copies preserve the withheld
status, including compressed video/audio packet copies, so copying a frame for
async processing does not erase it. Standalone
metadata capture still reports invalid text as an error.

## Dependency and names

No Cargo features are enabled by default. Explicitly enable `image-encoding`
for image methods and `ImageFormat`. Remove `advanced_sdk` from dependency
declarations: that 2.x feature had no effect and does not exist in 3.0.
Enable `advanced` when using the [Advanced SDK APIs](../advanced.md), and
select the runtime edition as described under [deployment](#runtime-and-deployment).
If using `#[tokio::main]` or Tokio's multithreaded runtime, enable Tokio's
`macros` and `rt-multi-thread` yourself; this crate enables only `rt`.

| 2.x | 3.0 |
| --- | --- |
| `NDI` | `Ndi` |
| `PixelFormat::BGRA`, `UYVY`, `NV12`, … | `Bgra`, `Uyvy`, `Nv12`, … |
| `ReceiverColorFormat::RGBX_RGBA`, `UYVY_BGRA`, … | `RgbxRgba`, `UyvyBgra`, … |
| `AudioFormat::FLTP` | `AudioFormat::Fltp` |
| `grafton_ndi::tokio::AsyncReceiver` | `grafton_ndi::asynchronous::tokio::AsyncReceiver` |
| `grafton_ndi::smol::AsyncReceiver` | `grafton_ndi::asynchronous::smol::AsyncReceiver` |

The crate root no longer shadows the `tokio` or `smol` dependency names.

## Runtime and deployment

Desktop and Android builds load NDI at runtime instead of linking it at build
time. They need no build-time SDK for the default features. Advanced native
operations still need Advanced headers and `libclang`; Apple mobile targets
still link a static SDK archive. See [build requirements](../setup.md#build-requirements).

- Handle `Error::RuntimeLoadFailed(failure)` during selection. Inspect
  `failure.loaded_any()` and its typed attempts before treating it as a missing
  library; installed libraries can load and then be refused. A missing dynamic
  library no longer prevents the process starting.
- Package the runtime explicitly: executable dependency scanners cannot find a
  dynamically selected library.
- Check the [search order](../setup.md#finding-the-runtime). Executable-local
  libraries and `NDI_RUNTIME_DIR_V6` precede the system loader. Request
  `SdkEdition::Advanced` when needed; an SDK installed on the build machine no
  longer chooses the runtime edition.
- Use an absolute `NDI_RUNTIME_DIR_V6`: relative values are refused and
  skipped. Explicit `library_path` values must be absolute on every target;
  relative paths return `InvalidInput` before selection, including on Apple
  mobile targets.
- Select once with the intended options. Successful selection lasts for the
  process; selecting another library later returns `Error::RuntimeConflict`.
- On dynamically loaded non-Apple ELF targets, a runtime already linked or
  preloaded into the process's global symbol scope must be the selected module.
  Other candidates are refused before loading, and an explicit different file
  returns `SelectionConflict::ForeignRuntimeInScope`. Select the runtime named
  in the diagnostic, or remove the other runtime's direct link or preload.
- Code declaring its own NDI `extern "C"` functions must link its own library;
  this crate no longer supplies that link or exposes its loaded symbols.
- Keep a runtime in test jobs that exercise NDI. Ordinary compile-only jobs
  need none; remove stale SDK environment variables where they are unnecessary.

| Removed API | Replacement |
| --- | --- |
| `NDI::is_supported_cpu()` | `Runtime::select(&options)?.is_supported_cpu()`, or `ndi.runtime().is_supported_cpu()` |
| `NDI::version()?` | `ndi.info().raw_version()`, or `Runtime::select(&options)?.info().raw_version()` before initialization |

The replacement version expression borrows runtime information rather than
returning a `String`; call `.to_owned()` where ownership is required.

## Options

Options have private fields and chainable setters. Remove the options builders
and their final `.build()`:

```diff
-let finder_options = FinderOptions::builder().show_local_sources(false).build();
+let finder_options = FinderOptions::new().show_local_sources(false);
-let options = ReceiverOptions::builder(source).color(ReceiverColorFormat::RGBX_RGBA).build();
+let options = ReceiverOptions::new(source).color_format(ReceiverColorFormat::RgbxRgba);
-let options = SenderOptions::builder("Camera 1").clock_audio(false).build();
+let options = SenderOptions::new("Camera 1").clock_audio(false);
```

`FinderOptionsBuilder`, `ReceiverOptionsBuilder` and `SenderOptionsBuilder` are
removed. Receiver presets move to `ReceiverOptions` itself. Replace the public
`ndi_recv_name` field with `.name(...)`, and inspect settings with
`configured_*()` getters. These report requested configuration, not runtime
acceptance. Struct literals and direct field reads must change.

`ReceiverOptions` has no `Default`: construct it with a source.
`ReceiverOptions::new(source)` allows video fields, matching the old builder;
add `.allow_video_fields(false)` to preserve the old `Default` behavior.
Finder local-source visibility, sender clocks and receiver color/bandwidth
keep their old defaults.

## Sources

Construct sources with `Source::new(name).with_address(address)` and read them
with `name()` and `address()`. `address()` returns `Option<&SourceAddress>`;
`SourceAddress::None`, and `Default` for both types, are removed.
`Source::host()` replaces `ip_address()` and may return a URL hostname.

Both `SourceAddress::Ip(text)` and `SourceAddress::Url(text)` become
`SourceAddress::new(text)`. Replace variant matching with `as_str()` and
`is_url()`, which checks for `://` in the opaque address text. Source equality
and hashing compare the name and address text, including for configured and
discovered sources constructed through different paths.

Choose an exact feed with `finder.find_source_by_name(name, timeout)`, or
`find_source(timeout, predicate)` to disambiguate descriptors. The first
matching descriptor wins; duplicate names need an application predicate.

Replace `Finder::wait_for_sources` with one persistent `SourceWatch` per
consumer. Take snapshots and wait through that same cursor:

```diff
-let sources = finder.current_sources()?;
-finder.wait_for_sources(timeout)?;
+let mut watch = finder.watch(); // Keep this watch across iterations.
+let sources = watch.current_sources()?;
+watch.wait_for_change(timeout)?;
```

A report published by another lookup after the snapshot remains visible to the
next wait, including a zero-timeout poll. A watch is `Send` but not `Sync`;
independent consumers each create their own watch.

```diff
-let cache = SourceCache::new();
-let source = cache.find_by_host("192.168.1.100", timeout)?;
+let cache = SourceCache::new(finder);
+let feeds = cache.sources_by_host("192.168.1.100", timeout)?;
```

The cache **owns the configured Finder**, including its runtime lifetime and
discovery scope. It has no lifetime parameter or `Default`; move the finder
into it and use `cache.finder()` for later uncached lookups. `sources_by_host`
returns all distinct matching feeds observed over the complete window; select
the desired feed yourself. Entries remain stale until invalidated. See the
[server-state recipe](../usage.md#keep-discovery-in-server-state).

Async code can use `asynchronous::<runtime>::AsyncFinder`, `AsyncSourceCache`
and owned `AsyncSourceWatch` instead of wrapping lookups in `spawn_blocking`.
Their dropped waits stop workers between native attempts and preserve cursors.

Finder results and discovery windows now enforce count and byte limits and
return `Error::ResourceLimit` rather than a partial result. A lookup's timeout
also covers snapshot-lock waits. Zero makes one non-waiting attempt, but native
copying and application predicates are not interrupted. Oversized timeouts are
rejected even on cache hits.

## Frames

Widths, heights, rates and counts move from `i32` to `u32`; strides move to
`usize`. Buffer-length results were already `usize` in 2.0. Values outside the
signed native ABI range are rejected before submission.

| 2.x | 3.0 |
| --- | --- |
| `VideoFrameBuilder::new()` | `VideoFrame::builder()` |
| `AudioFrameBuilder::new()` | `AudioFrame::builder()` |
| `.frame_rate(n, d)` | `.frame_rate(FrameRate::new(n, d)?)` |
| `.aspect_ratio(ratio)` | `.picture_aspect_ratio(ratio)` |
| `.channels(n)`, `.samples(n)` | `.num_channels(n)`, `.num_samples(n)` |
| `.channel_stride_in_bytes()` | `.channel_stride_bytes()` |
| `.frame_rate_n()`, `.frame_rate_d()` | `.frame_rate().numerator()`, `.frame_rate().denominator()` |
| `.line_stride_or_size()` and `LineStrideOrSize` | `.line_stride_bytes()` |
| `PixelFormat::try_line_stride(width)` | `PixelFormat::line_stride_bytes(width)` |
| `PixelFormat::try_buffer_size(width, height)` | `PixelFormat::buffer_len(width, height)` |
| `PixelFormatInfo::try_buffer_len(stride, height)` | `PixelFormatInfo::buffer_len(stride, height)` |

`VideoFrame`, `AudioFrame`, `MetadataFrame`, `VideoFrameBuilder` and
`AudioFrameBuilder` lose `Default`. `AudioFrameBuilder::format` is removed because audio uses
`AudioFormat::Fltp`. Frame-rate setters take an
already validated `FrameRate` and no longer return `Result`. Rates compare and
hash by value (`30/1 == 60/2`), while retaining their supplied numerator and
denominator for accessors and submission.

**Review defaults.** Owned and borrowed video builders store the SDK square-pixel
aspect request, `0.0`, instead of a fixed display ratio. Set a positive
`picture_aspect_ratio` for anamorphic output. Owned and borrowed video builders
and `VideoPacketFormat::new` default to 60 fps; explicitly choose another rate
when required. Copies preserve supplied timing and aspect.

Use `Timecode::from_ticks(value)` instead of raw `i64`; `.ticks()` extracts it.
The default remains `Timecode::SYNTHESIZE`. Create metadata with
`MetadataFrame::new(text)?.with_timecode(timecode)`, replacing
`MetadataFrame::with_data(text, ticks)` and empty `new()`.
Received timestamps are `Option<SdkTimestamp>` instead of raw `i64`.
Delete send-frame timestamp setters and `BorrowedVideoFrame::timestamp`.

Use `FourCc::from(pixel_format)`, `fourcc.raw()` and
`PixelFormat::try_from(fourcc)` instead of raw integer conversions for pixel
formats. `ScanType` and `AudioFormat` also lose their raw integer conversions.

Borrowed media `to_owned()` is infallible, including FrameSync references;
remove `?`. `BorrowedVideoFrame::try_to_owned` becomes `to_owned`. Reuse existing
storage with `copy_into`. `VideoFrame::from_raw` is removed.

Owned video/audio `set_metadata(Some(text))` becomes `set_metadata(text)`;
`set_metadata(None)` becomes `clear_metadata()`. Invalid replacement metadata
leaves the old value intact.

`VideoFrameBuilder::build`, `AudioFrameBuilder::build` and owned-frame
`replace_data` return refused input in `Rejected<T>`. `?` still converts it to
`Error`. When returning the result directly, use
`Ok(builder.build()?)` or `.map_err(Error::from)`. Inspect `rejected.error()`
and recover input with `into_inner()` instead of discarding reusable storage.

## Receiving

Capture returns `Result<Option<Frame>>`: handle timeout as `None` instead of
`Error::FrameTimeout`. Remove `try_capture`; rename `try_capture_ref` to
`capture_ref`. Async capture follows the same rule.

```diff
-if let Some(frame) = receiver.video().try_capture(timeout)? {
+if let Some(frame) = receiver.video().capture(timeout)? {
     println!("{}x{}", frame.width(), frame.height());
 }
```

Unlike the old `try_*` methods, capture retries transient SDK results until a
frame arrives or the full deadline is spent. Use `Duration::ZERO` for one
non-waiting attempt. `CaptureKind::ref_to_owned` is private; call the frame's
`to_owned()`.

`Receiver::source()` becomes `connection_target()`, an owned snapshot of the
last requested target. `connect_to(B)` changes it to B, `disconnect()` retains
B and `reconnect()` retries B. Retain the original source yourself to return
to it. Observe actual source changes with `poll_source_name_change`.

`Receiver::poll_status_change(timeout)` becomes `poll_event(timeout)`:

```diff
-if let Some(status) = receiver.poll_status_change(timeout)? {
-    println!("connections: {}", status.connections);
+if let Some(ReceiverEvent::StatusChanged(status)) = receiver.poll_event(timeout)? {
+    println!("connections: {}", status.connections());
 }
```

It can also return source-change and unknown events, and waits through
transient results for the full timeout. Combined capture and `poll_event`
consume pending events once; typed capture retains them for either consumer.
Notifications coalesce and are not a broadcast or ordered history. Connection
loss can produce no status event; query `is_connected()` or `connection_stats()`
when tracking connections, even when `poll_event()` returns no item.

`FrameSync::receiver()` and `advanced::AvSync::receiver()`, including their KVM
views, no longer grant event polling: native synchronization can consume those
notifications. Typed metadata capture remains available. Replace those polls
with capability getters (`ptz().is_supported()`, `web_control_url()` and KVM
support), `poll_source_name_change()`, or connection queries (`is_connected()`
and `connection_stats()`). Generic metadata helpers use `MetadataMode`; helpers
that poll events need the separate `EventMode` bound.

| Receiver API | Required generic mode bound |
| --- | --- |
| Common controls | `ReceiverMode` |
| Metadata capture | `MetadataMode` |
| Event polling | `EventMode` |
| Audio capture | `CaptureMode` |
| Video capture | `VideoMode` |

Update generic functions previously bounded only by `ReceiverMode`.
FrameSync's attached receiver exposes metadata and controls, not raw audio or
video. Capture through FrameSync, or call `into_receiver()` first.

PTZ moves to `receiver.ptz()`: remove the `ptz_` method prefix, rename
`ptz_exposure_manual_v2` to `exposure_manual_detailed`, and pass preset indices
as `u8` in `0..=99`. Rejected commands return `NativeOperationFailed`.
`set_tally` takes `Tally` by value and returns `()`; `send_metadata` returns
`Result<()>`, with `Error::NotConnected` where it previously returned `false`.
`Tally`, `ReceiverStatus` and `ConnectionStats` expose getters instead of
public fields, for example `tally.on_program()` and `stats.connections()`.

## FrameSync

**The short capture names now return owned copies.** Calls using only common
frame methods may still compile while introducing a copy:

```diff
-let video = framesync.capture_video(ScanType::Progressive)?;
+let video = framesync.capture_video_ref(ScanType::Progressive)?;
-let audio = framesync.capture_audio(request)?;
+let audio = framesync.capture_audio_ref(request)?;
```

Rename `capture_video_owned` to `capture_video`, and `capture_audio_owned` to
`capture_audio`, when you want owned output. `FrameSync::new` returns a
rejected receiver in `Rejected<Receiver>` on failure; `?` still converts it.

`FrameSyncAudioRequest::capture_with(Some(rate), channels, samples)` becomes
`capture_at(rate, channels, samples)`, with unsigned dimensions. Requests must
specify a positive sample rate. Replace `capture_with(None, ...)` and the
input-format query with:

```diff
-let input = framesync.capture_audio(FrameSyncAudioRequest::query_input())?;
-if input.num_channels() > 0 {
-    let request = FrameSyncAudioRequest::capture_with(None, input.num_channels(), 1_024)?;
+if let Some(input) = framesync.audio_input_format()? {
+    let request = FrameSyncAudioRequest::for_input(input, 1_024)?;
```

`capture_audio` returns `AudioFrame`, not `Option<AudioFrame>`; the borrowed
version returns `FrameSyncAudioRef`. Remove `is_empty` checks; `format()` and
`to_owned()` return their values directly. `audio_queue_depth()` returns
`Result<u32>` and rejects negative native counts.
Do not use clocked output or a known format as proof of recent input; use the
[reception-monitor recipe](../usage.md#monitor-reception-of-the-expected-media).

## KVM receiver access

For users of the unreleased Advanced API, `KvmSession::receiver()` now returns
`advanced::KvmReceiver<'_, M>` instead of `&Receiver<M>`. Replace explicit
receiver-reference annotations with this view (or let inference supply it).
Capture, events, diagnostics, tally, PTZ, metadata and other compatible shared
controls retain their mode bounds. Borrowed frames can still be held across
input calls. Packet sessions continue to capture through `session.capture()`.

The view cannot `connect_to`, `disconnect`, `reconnect`, or recover an
unrestricted receiver. Move those calls after successful `release_all()` and
session termination; there is no deprecated bypass. This applies to ordinary,
FrameSync, AVSync, packet and allocator-backed sessions:

```rust,no_run
use grafton_ndi::{Receiver, Result, Source};
use std::time::Duration;

fn switch(receiver: &mut Receiver, next_source: &Source) -> Result<()> {
    let mut session = receiver.kvm()?;
    session.key_down(0xffe1)?;
    let frame = session.receiver().video().capture_ref(Duration::ZERO)?;
    session.release_all()?; // Retry failures before proceeding with a switch.
    drop(frame);
    drop(session);
    receiver.connect_to(next_source)?;
    let _session = receiver.kvm()?;
    Ok(())
}

fn main() {
    let _ = switch;
}
```

For attached owners, end the session and outstanding split/frame borrows, then
change the connection through `owner.receiver()` before `owner.controls().kvm()`.
Application connection changes are excluded during the session. Native source
loss, Discovery Server remote control and failed release delivery can still
leave input unresolved; Drop remains best effort.

## Sending

`send_video(&frame)` now returns `Result<()>`; `send_video_async(frame)` can
return `Rejected<VideoFrame>`. Use `?`, or recover an unsent frame with
`into_inner()`. Sends check the runtime's format capabilities before submission.

`sender.tally()` returns the current tally. Replace the old
`tally(timeout)` with `wait_for_tally_change(timeout)` when waiting for a
change; polling no longer loses the current state after the first read.
Polling also preserves a change for the next waiter. Changes coalesce and are
reported once. Each wait spends one timeout budget on lock contention and the
native query.
While a waiter holds the native query, polls return the most recently cached
state without blocking.

Synchronous video/audio operations borrow a shared reference to a validated
source, including captured frames. Remove `BorrowedVideoFrame::from(&owned)`
and old `Into<BorrowedVideoFrame>` adapters. Use `send_video_async_copy(&frame)`
to copy a captured or borrowed frame into reusable sender-owned storage before
submission. It returns `Result<()>`; it keeps the frame the SDK released as
storage for a later copy. Owned submissions still return their displaced
frame, and `finish_video_async` returns the final frame and releases any spare.
`Sender` still means `Sender<RawSend>`; generic senders use `SenderMode`, with
`AudioSendMode` required for audio sends.

`Sender::on_async_video_done` and `clear_async_video_done` are removed. Observe
completion through the owned frames returned by `send_video_async` and
`finish_video_async`; their buffers are safe to reuse when returned.

Construct borrowed video with the builder:

```diff
-let frame = BorrowedVideoFrame::try_from_uncompressed(&pixels, 1920, 1080, PixelFormat::BGRA, 30, 1)?;
+let frame = BorrowedVideoFrame::builder(&pixels, 1920, 1080, PixelFormat::Bgra)
+    .frame_rate(FrameRate::new(30, 1)?)
+    .build()?;
```

Use `line_stride_bytes(usize)`, `frame_rate(FrameRate)` and
`timecode(Timecode)`. Replace `fourcc()` with `FourCc::from(frame.pixel_format())`,
and `validated_data_len()` with `storage().len()`. `storage()` covers validated
frame storage including row padding, **not the whole original input slice** or
extra SDK tail room. `BorrowedVideoFrame::data()` now returns `Option<&[u8]>`:
active bytes only, or `None` when padding separates rows or planes. A single
padded row still returns `Some` of its active bytes.

Every video or audio frame has inherent `timestamp`, `to_owned` and `copy_into` methods; video
frames also have `sends_in_place`. Application-built borrowed video returns
`None` for its timestamp. Owned `data()` remains an infallible packed slice;
its trait form wraps that same slice in `Some`, and both `to_owned` forms clone
that same owned storage.

On targets needing SDK tail room, borrowed UYVY/UYVA sends stage active rows
with a zeroed tail by default; padded captures also stage active rows. The
sender reuses staging storage.
Inspect `frame.sends_in_place()` when this matters to your pipeline.
For direct borrowed sending, explicitly opt into
`allow_send_from_padding_and_tail(true)` and provide the length computed by
`PixelFormat::send_buffer_len`. This permits encoding initialized padding and
tail bytes into the picture. `unsafe readable_after` alone does not opt in;
its bytes must be initialized, stable and in the same live allocation. Keep
this choice explicit rather than removing the default sanitization.

## Image encoding

Enable `image-encoding` and import `ImageFormat` from the crate root. Existing
`encode_png`, `encode_jpeg` and `encode_data_url` signatures remain, with these
behavior changes:

- JPEG quality outside `1..=100` is `InvalidInput`, previously `InvalidFrame`.
- JPEG now enables runtime SIMD dispatch. Encoded bytes and reconstructed
  pixels can vary with CPU capabilities; scalar JPEG and PNG retain their
  legacy byte-identity coverage. Use decoded-quality comparisons for JPEG.
- PQ/HLG frames are refused by default, including RGB. To retain their code
  values, request PNG with `HdrPolicy::CodeValues`.
- Unreadable `ndi_color_info`, including metadata withheld as `NotUtf8` or
  `Unterminated`, is refused under the default color policy. `color_info()`
  also refuses withheld metadata. Owned copies preserve the status and the
  same refusal. Use `ColorPolicy::Override { matrix, range }` only when the
  application can supply that information.
- PNG carries BT.2020 color metadata where applicable, changing encoded bytes.
- YUV formats can encode; do not use an `InvalidFrame` result to identify them.
- `ImageFormat` gains `WebpLossless` and `WebpLossy(quality)`.
- `ImageWorkspace` optionally retains conversion scratch across snapshots;
  existing frame convenience methods remain available.

See [image encoding](../image-encoding.md) for current format and color choices.

## Errors and timeouts

Synchronous `Receiver::reconnect()` now returns `()` and reuses its retained,
validated native target. Remove `?` or `.unwrap()` from those calls. Async
`reconnect().await` still returns `Result<()>` for blocking-task submission.

`InvalidFrame`, `InvalidInput` and `UnexpectedSdkResult` now carry
`FrameDefect`, `InputDefect` and `SdkResultDefect`, respectively. Match their
variants and evidence instead of searching diagnostic strings. For example,
`InvalidFrame(FrameDefect::HdrRefused { transfer })` identifies the refusal
that permits a `HdrPolicy::CodeValues` PNG fallback;
`FrameDefect::ColorMetadataWithheld { status }` identifies when a color-policy
override is required. These public cause enums are non-exhaustive.

Layout refusals now have one public `LayoutDefect`, shared by both outer
classifications. Match `Error::InvalidFrame(FrameDefect::Layout(cause)) |
Error::InvalidInput(InputDefect::Layout(cause))` to inspect the same layout
cause regardless of whether it came from a frame or a standalone aspect ratio,
frame rate, compressed video format or allocation stride. The former direct
layout variants move under `Layout`; a zero height is always
`LayoutDefect::VideoHeight(0.into())`.

Native operation failures and the `operation` fields in `SdkResultDefect`
carry `NativeFunction`. Match the function with a guard, for example
`Error::NativeOperationFailed { operation } if operation == c"NDIlib_routing_clear"`.
Its `name()` returns the static `CStr`; `Display` prints the entry-point name.
Every failure names the function actually called, including File operations:
`NDIlib_file_recorder_start` and `NDIlib_file_recorder_start_with_timecode`
are distinct. Replace matches on labels such as "routing clear" or
"recorder start" with the corresponding SDK function.

Numeric layout evidence uses `DiagnosticInteger`; timeout and delay evidence
uses `DiagnosticDuration`. Their `get()` methods return the original `i64`
and `Duration`. Fixed 32-bit words keep these copyable values allocation-free
and preserve the compact error budget on 32-bit MSVC as well as other targets.

`CaptureFailed` is replaced by `ConnectionLost` for a receiver's error frame.
A sender's unexpected capture type is
`UnexpectedSdkResult(SdkResultDefect::UnexpectedFrameType { .. })`.
`InitializationFailed` carries `InitializationFailure::NotStarted` or
`InitializationFailure::HandleCountExhausted`. `InvalidUtf8` retains the
original `std::str::Utf8Error`, including `valid_up_to()` and `error_len()`.

Common layout, timeout, HDR and withheld-metadata refusals retain their evidence inline and allocate nothing;
formatting their diagnostics is separate. Wide diagnostic evidence uses
`CompactDiagnostic<T>`, which dereferences to its public evidence fields. It
is inline on 64-bit targets; on 32-bit targets it boxes only invalid frame-rate
components, compressed dimensions, detailed short video strides, audio
data-length mismatches, compressed-audio quantities and PTZ bounds. This
cold-path exception preserves the original per-target `Error` size budget.
To preserve arbitrary diagnostic
text, `FrameDefect::ColorMetadata` and `FrameDefect::EncodingFailed` retain
boxed peer-text or encoder diagnostics, and
`InputDefect::FilenamePatternToken` and `InputDefect::DiscoveryAddressRejected`
retain boxed caller text. Those two cause enums implement `Clone`, rather
than `Copy`. `AudioCountKind::Channels` and `AudioCountKind::Samples` identify
the audio count without a text discriminator. Malformed Advanced
JSON retains its fixed redacted message and does not preserve the input text.

The `symbol` fields of `LoadRefusal::MissingEntryPoint` and
`LoadRefusal::EntryPointOutsideModule`, and `first_missing` of
`LoadRefusal::NoCompleteFileFamily`, now borrow `&'static CStr`. Compare with
C-string literals, such as `c"NDIlib_initialize"`; use `to_string_lossy()`
for diagnostic text.

Selection errors carry typed causes and paths. Match
`Error::RuntimeConflict(failure)` and inspect `failure.kind()` for the
`SelectionConflict`, `library()` for core or File, and `selected()`,
`requested()` and `foreign_module()` for the relevant paths. Optional paths
are absent when that kind of conflict has no such location. Use
`failure.to_string()` for diagnostic text.
`RuntimeLoadFailed(failure)` now carries `LoadFailure`: use `library()`,
`attempts()` and `loaded_any()`, and match each attempt's `LoadRefusal` and
`LoadOrigin`. Use `failure.to_string()` to obtain the previous diagnostic text;
substring matching is no longer needed. These cause enums are non-exhaustive,
so keep a wildcard arm.

Runtime capability refusals use
`Error::UnsupportedCapability { feature, refusal }` and
`CapabilityStatus::Unavailable(refusal)`. Both carry the same
`CapabilityRefusal`; `reason()` returns its `CapabilityUnavailable` category.
Match the refusal variant for a missing symbol, absent declaration, edition
or required version instead of parsing text. Required versions borrow static
registry values. Read the runtime's reported version separately through
`ndi.info()` when needed.

File operations report a missing family with
`Error::FileFamilyUnavailable { family, missing }`; `missing` is a static
`CStr` naming the entry point. Match this variant alongside
`UnsupportedCapability` when handling every unavailable operation. The runtime
capability enum has no `File` variant; query `FileApi::status` or `supports`.

| 2.x variant | 3.0 handling |
| --- | --- |
| `InvalidConfiguration` | `InvalidInput` |
| `FrameTimeout` | Capture returns `Ok(None)` |
| `NullPointer`, `PtzCommandFailed` | `NativeOperationFailed`, naming the native operation |
| `Timeout` from a negative connection count | `UnexpectedSdkResult` |
| `SourceUnavailable`, `Disconnected` | Delete unused match arms; 2.0 never returned these |

A CPU missing required instructions yields `UnsupportedCpu`; SDK object creation
failure yields `NativeOperationFailed`. `InitializationFailed` now means runtime
initialization failed. `Error::Io` is available only with `file-io` or
`image-encoding`. Keep a wildcard arm for the non-exhaustive error enum.
`ResourceLimit` uses typed `ResourceKind` values rather than string matching.

Async receiver callback and blocking-operation panics now unwind the awaiting
task with their original payload; SDK buffers are freed on the worker first.
Code matching `SpawnFailed` for panics must catch the unwind instead.
`SpawnFailed(SpawnFailure)` reports only `NoRuntime` or `TaskCancelled`.

`MAX_TIMEOUT` is `u32::MAX - 1` milliseconds; the 2.x constant was one
millisecond larger. Use the constant instead of a hard-coded maximum.
Positive waits round up to whole milliseconds; use `Duration::ZERO` to poll.
Rounding and the protection against the SDK's infinite-wait sentinel were
already included in 2.1.0; 3.0 also reduces the accepted maximum.

For the unreleased Advanced API, packet-envelope causes now agree across
contiguous, scatter and received packets. Match `PacketCodecMismatch` for a codec mismatch or
`EmptyCodecPayload` for an empty payload. Length overflow, truncation and
trailing bytes have distinct causes; received packets still retain extensions
and trailing bytes that send admission refuses.

### Router connection metadata

`Router::add_connection_metadata` and `Router::clear_connection_metadata` now
require `&mut Router`. Register metadata through the router's owner. Receivers
and routers keep owned copies until registration is cleared or they are destroyed.

The unreleased Advanced packet receiver now copies into `ReceivedVideoPacket`
and `ReceivedAudioPacket`, retaining all received envelope details. Move a
packet through `CompressedVideoFrame::try_from(packet)` (or the audio pair)
before sending; failures return it in `Rejected`. The reverse `From` conversion
returns sendable frame storage to a receive pool without allocation. For a
borrowed packet, `TryFrom<&CompressedVideoRef>` checks before making an owned
copy, while `try_copy_into` checks before reusing a sendable destination and
leaves it unchanged on refusal. Lossless `copy_into` targets a received packet.

Contiguous compressed `send_video` and `send_audio` return `()`, and
`send_video_async` returns `Option<SubmittedVideo>`. Remove the corresponding
`?` or `unwrap()`; use the checked receive-to-send conversion at the boundary.
Scatter operations still return their runtime capability refusals.

Owned metadata creation and replacement now return `Rejected<String>` on
failure, including `MetadataFrame::new`, `set_data` and every `set_metadata`.
`?` still converts a refusal into `Error`. When handling it directly, inspect
`rejected.error()` and recover the original string with `into_inner()`.
An interior-NUL `NulError::into_vec()` contains only the prefix through its
first NUL; the complete text is in `Rejected`. Rejected owned video and audio
builders expose `supplied_metadata()` and `take_metadata()` for repair.

### Native receive counts

`Receiver::connection_stats()` and its async/KVM views return
`Result<ConnectionStats>`. `FrameSync::audio_queue_depth()` and its capture view
return `Result<u32>`. Handle `UnexpectedSdkResult(SdkResultDefect::NegativeCount)`
when the SDK returns a negative count; previously these values became zero.
The cause retains exact 64-bit evidence through `DiagnosticInteger::get()`.
Status-event polling reports the same error without losing its invalidation.
`is_connected()` remains a boolean and returns false for a negative native count.
