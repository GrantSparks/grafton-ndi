# Migrating from 1.x to 2.0

Update the dependency to `grafton-ndi = "2.0"` and use Rust 1.88 or later.
The optional async-std integration is replaced by smol. This release requires a
major version because `NDI` can no longer be constructed directly and async sends now take ownership
of `VideoFrame`. Borrowed video `data()` is now optional, and owned video
copies normalize padded SDK layouts into tightly packed planes. The release
also changes async-send memory costs and corrects several SDK layout contracts.

## SDK and platform setup

The existing APIs have been validated with NDI SDK 6.3.2. Bindings are generated
from the installed headers, so point `NDI_SDK_DIR` at the intended SDK and make
its matching runtime libraries discoverable. The `advanced_sdk` feature still
does not select the installed SDK or enable Advanced-only functionality.

Android now supports ARM64, ARMv7, x86, and x86_64 builds using the Android NDI
SDK and NDK. Windows cross-builds recognize the installer's `Include` and `Lib`
directory casing on Linux hosts. Linux setup creates linker symlinks for all
shipped architectures. See [SDK validation](../sdk-validation.md) for commands,
runtime coverage, and Apple platform limitations, and the
[CI SDK maintenance guide](../../.github/actions/README.md) for URL secrets and
installer hash updates. Personalized download links should remain in secrets.

## Async-std to smol

Replace the `async-std` Cargo feature with `smol` and imports of
`grafton_ndi::async_std::AsyncReceiver` with `grafton_ndi::smol::AsyncReceiver`.
The old feature and module have been removed. Tokio integration remains available.

```toml
[dependencies]
grafton-ndi = { version = "2.0", features = ["smol"] }
smol = "2.0.2"
```

Replace `async_std::task::block_on` with `smol::block_on`. Replace async-std
entry-point attributes with a synchronous entry point that calls `smol::block_on`:

```rust
use grafton_ndi::smol::AsyncReceiver;

fn main() -> grafton_ndi::Result<()> {
    smol::block_on(async {
        // Build an AsyncReceiver, then await its capture methods here.
        Ok(())
    })
}
```

Both adapters retain the same panic conversion, cancellation gate, and shared
capture deadline. An application migrating from async-std must also migrate its
other runtime-specific calls.

Refresh application lockfiles to resolve `event-listener` to 5.4.2 or later;
for an existing affected resolution, run
`cargo update -p event-listener@5.4.1 --precise 5.4.2`. Library manifests cannot
repair a consuming application's lockfile. CI generates a fresh library lockfile
and rejects vulnerabilities and informational warnings with
`cargo audit --deny warnings`.

## Runtime handles

Replace direct unit construction (`let ndi = NDI;`) with checked initialization:

```rust
use grafton_ndi::NDI;

fn main() -> Result<(), grafton_ndi::Error> {
    let ndi = NDI::new()?;
    let another_handle = ndi.clone();
    drop(another_handle);
    drop(ndi);
    Ok(())
}
```

Each constructed or cloned handle owns a runtime reference. Sender, receiver,
and finder constructors still accept `&NDI` and keep their own live handles.

## Async video sends take ownership

`Sender::send_video_async` now takes a `VideoFrame` by value and returns
`Option<VideoFrame>` instead of a token. The sender retains the submitted frame
while the SDK uses its pixels and metadata. A subsequent send synchronizes the
previous submission and returns that completed frame for reuse. Moving a frame
does not allocate or copy its pixel buffer in the Rust wrapper; SDK encoding
and network processing may still copy data.

Use two frames to overlap rendering with transmission:

```rust
use grafton_ndi::{Sender, SenderOptions, VideoFrameBuilder, NDI};

fn main() -> Result<(), grafton_ndi::Error> {
    let ndi = NDI::new()?;
    let options = SenderOptions::builder("Owned async sender").build();
    let mut sender = Sender::new(&ndi, &options)?;
    let first = VideoFrameBuilder::new().build()?;
    let mut available = VideoFrameBuilder::new().build()?;
    assert!(sender.send_video_async(first).is_none());
    for value in 0..60u8 {
        available.data_mut().fill(value);
        available = sender.send_video_async(available).expect("previous frame");
    }
    let final_frame = sender.finish_video_async().expect("final frame");
    drop((available, final_frame));
    Ok(())
}
```

`finish_video_async()` submits the SDK's null-frame synchronization boundary and
returns the final owned frame. Sender destruction also drains pending work.
`flush_async_blocking()` completes transmission but retains the owned frame for
recovery by the next send or finish. The misleading `flush_async(timeout)` method
is removed: use `flush_async_blocking()` when you need explicit synchronization,
or `finish_video_async()` when you also need the final owned frame back. These
SDK synchronization calls block until completion and have no timeout argument.

For borrowed application buffers, use
`send_video_async_copy(&borrowed_frame)? -> Option<VideoFrame>`. This copies validated
pixels and metadata into an owned frame, then uses exactly the same
submission/recovery path. The application can immediately mutate or release its
source buffer. The previous frame is returned regardless of whether it was
submitted through the owned or copying path. Invalid application buffers are rejected during borrowed-frame construction,
before submission. `BorrowedVideoFrame::try_to_owned()` exposes this
conversion separately.

`AsyncVideoToken` and the public `waitable_completion` module are removed.
Completion is observed at a subsequent send, explicit finish/flush, or sender
destruction. `on_async_video_done` now requires mutable sender access and
replaces the existing handler; `clear_async_video_done` removes it. Handlers run
once per submission on the synchronizing thread, outside internal locks. A
handler panic propagates after ownership is safe, but can drop a completed frame
before it is returned. No SDK completion callback is registered, even with
`advanced_sdk`. This retained compatibility flag does not enable additional
Advanced-only functionality. Do not wait for a callback before submitting the
next frame.
Borrowed receive APIs remain zero-copy. `BorrowedVideoFrame::from_parts_unchecked`
and `LineStrideOrSize::DataSizeBytes` are removed: opaque payloads had no supported
consumer in the owned async pipeline. Borrowed `pixel_format()` and
`validated_data_len()` now return concrete values rather than `Option`.

## Video widths and multi-plane layouts

Every supported uncompressed pixel format now requires a positive **even
width**, including BGRA, BGRX, RGBA, and RGBX. Crop or pad odd-width input before
building frames. Sizing helpers and receive validation enforce the same rule.
Planar and semi-planar 4:2:0 formats retain their even-height requirements.

For UYVA, P216, and PA16, `try_line_stride()` describes the first plane rather
than aggregate bytes across all planes. `info().bytes_per_pixel()` now returns
`2` for these formats (previously `3`, `4`, and `4`, respectively).

| Format | Tight first-plane stride | Plane layout | Tight total buffer size |
| --- | --- | --- | --- |
| UYVA | `2 * width` | UYVY, then 8-bit alpha with half the first-plane stride | `3 * width * height` |
| P216 | `2 * width` | 16-bit Y, then interleaved 16-bit CbCr at the same stride | `4 * width * height` |
| PA16 | `2 * width` | P216 planes, then 16-bit alpha at the same stride | `6 * width * height` |

Use `PixelFormat::try_buffer_size` or `PixelFormatInfo::try_buffer_len` for
allocation. Multiplying width, height, and `bytes_per_pixel()` omits extra
planes. For padded frames, pass the actual first-plane stride to the checked
layout APIs. `FormatCategory` now also exposes `PackedAlpha`, `SemiPlanar422`,
and `SemiPlanar422Alpha`; keep a wildcard arm when matching this non-exhaustive
enum. Owned and borrowed receive validation use these corrected plane sizes.

## Borrowed video padding safety

`VideoFrameRef::data()` and `FrameSyncVideoRef::data()` now return
`Option<&[u8]>`, matching the borrowed audio policy. `Some` covers contiguous
active payload only. SDK row padding can be uninitialized, so padded frames
return `None` when gaps separate active rows or planes. A single packed row
can still return `Some`, excluding its trailing padding.

Replace flat borrowed access with optional contiguous access or active rows:

```rust
# use grafton_ndi::VideoFrameRef;
fn consume(frame: &VideoFrameRef<'_>) {
    if let Some(pixels) = frame.data() {
        // Contiguous active bytes in SDK plane order.
        println!("{} active bytes", pixels.len());
    } else {
        for plane in frame.planes() {
            for row in plane.rows() {
                println!("{} active row bytes", row.len());
            }
        }
    }
}
```

`plane(index)` returns an optional `VideoPlane`; `rows()` is a concrete,
exact-size iterator. `row(index)` supports indexed access. Plane metadata
provides `row_stride()`, `active_row_bytes()`, and `row_count()`.
Plane order is packed pixels, UYVY/A (UYVA), Y/CbCr[/A] (P216/PA16), Y/V/U
(YV12), Y/U/V (I420), or Y/UV (NV12). All views borrow the captured frame.

Use `frame.to_owned()?` when a flat owned buffer is required. Raw-to-owned,
receiver sync/async capture, FrameSync owned capture, and copied sends now copy
only active bytes into one tightly packed pixel allocation. Owned
`VideoFrame::data()` still returns `&[u8]`; its stride can shrink relative to the
source. For example, 642×32 BGRA at SDK stride 2,592 produces 82,176 owned bytes
at stride 2,568. Metadata, timing, aspect ratio, format, and scan type survive.
Do not reuse the source stride to index the normalized owned buffer.

PNG/JPEG/data-URL helpers on borrowed frames remain available and safely skip
padding without an intermediate owned frame. Their format/alpha policy is
unchanged, including the contiguous RGBA PNG fast path.

## Borrowed frame customization

Replace supported raw construction with `BorrowedVideoFrame::builder`. It
validates dimensions, explicit first-plane stride, slice extent, headers, and
bounded UTF-8 metadata without allocating. Immutable borrows retain those proofs
for getters and active-row copies. `try_from_uncompressed` remains the packed
convenience constructor and delegates to the same builder:

```rust
use grafton_ndi::{BorrowedVideoFrame, PixelFormat};

fn main() -> Result<(), grafton_ndi::Error> {
    let stride = 1920 * 4 + 16;
    let pixels = vec![0; stride * 1080];
    let frame = BorrowedVideoFrame::builder(&pixels, 1920, 1080, PixelFormat::BGRA)
        .line_stride(stride as i32)
        .frame_rate(30, 1)
        .metadata(c"<video/>")
        .timecode(10_000_000)
        .picture_aspect_ratio(0.0)
        .build()?;
    assert_eq!(frame.timecode(), 10_000_000);
    Ok(())
}
```

Timecodes use 100 ns units. Explicit zero remains a literal timecode; the default
requests SDK synthesis. Aspect ratio `0.0` selects square pixels; negative,
non-finite ratios are rejected. The borrowed constructor still defaults to 16:9.

## Discovery and async timeouts

Finder source snapshots now hold a per-finder lock from SDK retrieval through
copying into owned sources. Concurrent snapshot calls on one finder serialize;
public method signatures stay the same.

For both Tokio and smol adapters, `capture` and `try_capture` validate the
timeout before scheduling blocking work. The budget starts when the future is
first polled and includes time queued in the blocking pool. Queue delay reduces
the remaining SDK wait. This is a wait budget, not a wall-clock completion
deadline: queued work can still finish after the budget expires. Code requiring
a response deadline should account for that separately.

## Audio channel access

`FrameSyncAudioRequest` now has private fields. Replace raw `Capture` variants
and `NonZeroI32` arguments with a checked constructor, propagate its error once,
and reuse the copyable request:

```rust
use grafton_ndi::{FrameSync, FrameSyncAudioRequest};

fn capture(fs: &FrameSync) -> Result<(), grafton_ndi::Error> {
    let request = FrameSyncAudioRequest::capture_with(Some(48_000), 2, 1024)?;
    let borrowed = fs.capture_audio(request)?;
    let owned = fs.capture_audio_owned(request)?;
    Ok(())
}
```

Use `capture(channels, samples)?` or `capture_with(None, channels, samples)?` to
retain the source sample rate. `Some(rate)` must be positive; `Some(0)` is an
error. Both constructors require explicit positive channels and samples, reject
an unrepresentable signed byte stride and payloads above 64 MiB, and allocate
no sample storage. Successful construction and reuse allocate nothing in the
wrapper. Capture does not repeat dimension checks or add a format query or lock;
the SDK can still allocate, synchronize, and resample internally. The limit
bounds the requested sample payload, not total SDK memory use.

Automatic source channel selection has been removed. Replace `QueryInput` with
`query_input()`, then construct a request using the returned positive channel
count. Wait if no input format is available:

```rust
use grafton_ndi::{FrameSync, FrameSyncAudioRequest};

fn follow_source(fs: &FrameSync) -> Result<(), grafton_ndi::Error> {
    let format = fs.capture_audio(FrameSyncAudioRequest::query_input())?;
    if format.num_channels() <= 0 {
        return Ok(()); // Try again on a later application tick.
    }
    let request = FrameSyncAudioRequest::capture(format.num_channels(), 1024)?;
    drop(format);
    let audio = fs.capture_audio(request)?;
    Ok(())
}
```

Re-query and rebuild when your application chooses to follow source format
changes. Each request keeps its explicit output count even when the source
changes after the query: the SDK converts to that count. Both borrowed and owned
capture use this validated path and still validate returned descriptors and
metadata before exposing samples.

Borrowed `AudioFrameRef::data()` and `FrameSyncAudioRef::data()` now return
`Option<&[f32]>`: `Some` for packed samples and `None` for multichannel inter-channel padding. Mono frames expose their active
samples; empty FrameSync audio exposes `Some(&[])`.
Use `channel_data(index)` or `channels()` for allocation-free access to either
layout. Padding is never exposed as initialized samples. `to_owned()` copies
channels into packed owned storage, so the resulting stride can differ from the
SDK frame. `AudioFrame::channel_data()` now borrows `&[f32]` rather than allocating
a `Vec`; call `.to_vec()` explicitly when a separate allocation is needed.
`channel_data_mut()` supports in-place processing.

## Reusable frames and image encoding

`VideoFrame::default()` now uses Progressive scanning, matching the builder.
Use `set_timecode`, `set_timestamp`, and `set_scan_type` to update a recycled
frame. `VideoFrame::builder().data(existing_pixels).build()?` validates and takes
ownership of an existing `Vec<u8>` without allocating a discarded replacement.
With `image-encoding`, borrowed receiver and FrameSync video frames expose the
same PNG/JPEG/data-URL helpers as owned frames; no intermediate owned frame is
required.

## Discovery configuration and cache construction

Replace `SourceCache::new()?` with `SourceCache::new()`. Construction is
infallible; runtime initialization and discovery errors arise on cache misses.
Cached descriptors own their strings and need no live runtime handle.
`FinderOptions::default()` now includes local sources, matching the builder.
`find_sources` returns every descriptor observed during the discovery window in
first-observed order, not merely the final snapshot. Structural equality and
hashing include both name and address variant; they do not represent persistent
device identity. Host/port helpers understand conventional IPv6 and URL
authorities and remain best-effort for opaque SDK addresses.

Host lookups now require a complete bare hostname or IP address. IPv6 literals
may be bracketed; equivalent IP spellings and hostname ASCII case match.
`Source::matches_host` and `SourceAddress::contains_host` use the same exact
comparison. `MACHINE (Source Name)` matches its machine component for hostname
queries. Replace partial-IP or source-label searches with explicit filtering of
`Finder::current_sources()` or `Finder::find_sources()` results. Invalidation
also prevents an older in-flight discovery from restoring a stale entry.

## Metadata send signatures

Construct or update a `MetadataFrame` with the existing fallible methods, then
call `sender.send_metadata(&frame)` or
`sender.add_connection_metadata(&frame)` without `?`. Receiver upstream sends
now return the SDK status directly: `let status = receiver.send_metadata(&frame);`.
The frame retains its validated C string for repeated sends, and `into_data()`
still returns an owned `String`.

## Receiver status, controls, and capture boundaries

`ReceiverStatus` now contains `connections: u32`. Remove accesses to `tally` and
`other`, which never provided meaningful values. Receiver tally is outbound:
use `receiver.set_tally(&tally)` to publish program/preview state upstream, and
`send_metadata(&frame)` to send metadata upstream. Their boolean result is the SDK status flag, whose disconnected behavior varies
across platforms; use `is_connected()` to query connection state. PTZ commands now reject non-finite/out-of-range
values before FFI, including presets outside 0..=99. Status polling propagates
SDK capture errors instead of silently treating them as no change.

`Receiver<Mode = RawCapture>` now uses sealed capability modes. Constructors
return the ordinary default mode. `FrameSync::receiver()` returns
`&Receiver<FrameSyncAttached>`: raw `video()` capture is unavailable at compile
time. Use FrameSync video capture, or consume `into_receiver()` to destroy the
synchronizer and restore the ordinary receiver. Audio, metadata, status, tally,
PTZ, source, and reconnect operations remain available through one common
implementation. Generic helpers using only those operations can accept either mode:

```rust
use grafton_ndi::{Receiver, ReceiverMode};
fn connected<M: ReceiverMode>(receiver: &Receiver<M>) -> bool {
    receiver.is_connected()
}
```

Helpers requiring raw video continue to accept `&Receiver`. Neither attached
receivers nor references convert to the ordinary mode; recovery consumes FrameSync.
Pending status notifications survive both mode transitions. Modes add no heap
allocation or dynamic dispatch; resource destruction retains the SDK runtime.

Borrowed receiver frame references can now cross scoped thread
boundaries, consistent with the SDK's cross-thread freeing contract; FrameSync
references retain their conservative thread restrictions.

Public capture traits expose only frame-kind/type associations and owned
conversion. Raw FFI strategy exports (`FrameFree`, `FrameSyncAudioFree`,
`FrameSyncVideoFree`) and crate-root generic reference reexports are removed (the generic types remain
available through `frames`). Use
`CaptureKind` and the named receiver/FrameSync frame-reference aliases.

## Async errors, cancellation, and SDK configuration

The capture budget now includes blocking-pool queueing and waiting for the
receiver's reconnect lock. Both adapters preserve the same absolute deadline.
Executor failures and blocking-task panics return `Error::SpawnFailed`; Tokio
calls without an active runtime return this error instead of panicking.
Dropping a polled future suppresses work that has not passed its cancellation
gate. A blocking task that already passed that gate cannot be interrupted,
including while it waits for the reconnect lock: it may still consume a frame or complete
a reconnect after the future is dropped. Avoid repeatedly cancelling in-flight
captures if every frame matters.

Changing `NDI_SDK_DIR` or included SDK headers now rebuilds bindings. Library
selection uses installed artifacts and the Cargo target, not directory names or
the build host. Cross-builds require a target SDK through `NDI_SDK_DIR` and target
C headers/sysroot through the C toolchain or `BINDGEN_EXTRA_CLANG_ARGS`. Linux
requires supported GNU targets; Windows requires supported MSVC targets.
